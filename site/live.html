Run a kernel. Ask what slowed it down.

Pick a test kernel and run it. Its 24 hardware counters fill in as the H100 records them. When the trace is captured, ask KernelTSLM about it.

This is a replay. Traces are real KernelSight recordings from one H100. Answers are the fine-tuned model's real outputs on these traces, streamed at their recorded speed. No GPU runs in your browser.

3. Ask KernelTSLM run a kernel first

The model reads the whole trace, so questions open once the run finishes.

The model was trained on four kinds of question: what limits the kernel, what ran when, how one counter behaves over time, and what kind of work it is. A typed question is matched to the closest of these.

Data: KernelSight by williamhtan, test split grouped by problem. Model: OpenTSLM-Flamingo on Gemma 3 4B, fine-tuned once on all four tasks (runs/mt_all, seed 0). Answers and timings: runs/mt_all/predictions_*_real.jsonl. Reference answers come from fixed rules over the counters.
